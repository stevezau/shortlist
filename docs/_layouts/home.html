Every Plex user gets their own recommendations

Shortlist reads what each person on your server actually watched and builds them a private “Picked for You” row on their Plex home screen — visible only to them, refreshed while they sleep.

Get started View source

Free and MIT licensed One container, /config volume No AI key required

The problem

Plex shows everyone the same rows

Everyone on your server faces the same blank-screen problem: a huge library and no idea what to put on. Plex's built-in recommendation shelves are identical for every account and lean on its own streaming catalogue — they don't know that your sister has watched every heist film you own and your dad hasn't touched one.

One row per person

Each account gets a different set of titles, chosen from their history — and Plex's label restrictions keep every other account from seeing it.

Only titles you actually own

Every pick is verified to exist in your library before it's shown. Nothing invented, no dead ends, no “available on a service you don't have”.

It tells you why

Every pick carries its reason — “Because you watched Heat”. No black box, and you can block a bad seed that's skewing someone's picks.

How it works

Four steps, every night

Shortlist runs on a schedule you set. Each run walks every enabled user independently, so one person's failure never blocks anyone else's row.

Read their history

Per-user watch history straight from your Plex server, using each share's own token. A 20-episode binge counts as one show, not twenty episodes.

Gather candidates

Similar titles from TMDB and Trakt, plus an optional live web search for current, well-reviewed picks — then filtered down to what's actually in your library.

Rank and explain

The built-in picker needs no keys and no cloud. Add an LLM — Claude, GPT, Gemini or a local Ollama — and it writes each pick's short “why” instead.

Deliver privately

The row is written to Plex hidden, the exclusions that keep it private are merged into everyone else's share, and only then is it promoted onto Home.

Privacy

A row nobody else can see

Plex has no per-user collections. What it does have is label restrictions: give a collection a label, then tell every other account to exclude that label. What's left is a collection only one person can see.

The order matters more than the mechanism. Get it wrong and a “private” row is briefly visible to your whole server. Every Shortlist run does this, in this order:

How the mechanism works

  1. Sweep firstRemove rows Plex can't hide for that library type, before anything else runs.
  2. Deliver hiddenWrite every row to Plex unpromoted — present, but on nobody's home screen.
  3. Merge the exclusionsAdd label!=shortlist_<user> into every other account's share filter, leaving their existing filters byte-identical.
  4. Then promoteOnly now do rows appear on shared Home — so a row is never visible before it's private.

Snapshotted before any change

Your share filters are recorded before the first write. Uninstall restores them exactly.

Merges, never rebuilds

Existing share filters are parsed and unioned, not reconstructed. Other tools' settings survive untouched.

Kometa-friendly

Only collections Shortlist created are ever modified. Anything else on your server is detected and skipped.

Where it fits

Built to sit alongside the rest of your stack

Shortlist does one narrow thing: a different row for each person, private to them, inside Plex. It is not trying to replace your collection manager, your request app or your monitoring — and it is careful not to stand on any of them.

It never touches what it didn't make

Only collections carrying Shortlist's own shortlist_* label are ever modified. Kometa's collections, and anything you built by hand, are detected and skipped.

It merges share filters, never rebuilds them

Existing conditions on an account's filters are parsed and left byte-for-byte identical. Shortlist adds only its own entries — and snapshots the original first.

It connects rather than duplicates

Tautulli for richer history, Radarr and Sonarr for gaps, Trakt and MDBList for candidates. All optional; the only requirements are Plex and a free TMDB key.

Quick start

Running in about ten minutes

Start the container, open the web UI, and the setup wizard walks you through connecting Plex, choosing users, and building your first rows.

docker compose 
mkdir shortlist && cd shortlist
curl -fsSLO https://raw.githubusercontent.com/stevezau/shortlist/master/docker-compose.example.yml
mv docker-compose.example.yml docker-compose.yml
docker compose up -d
docker run 
docker run -d --name shortlist \
  -p 5959:5959 \
  -e TZ=Etc/UTC \
  -e PUID=1000 -e PGID=1000 \
  -v /path/to/shortlist/config:/config \
  --restart unless-stopped \
  {{ site.ghcr }}:latest

Want to try it without touching your server? Add -e SHORTLIST_DRY_RUN=1 and Shortlist shows you exactly what it would do, writing nothing to Plex until you're happy.

Requires Plex Media Server 1.43.2.10687+, Plex Pass on the admin account, and a free TMDB key. Full requirements →
